# ModelGym 模型训练

ModelGym 在 RackTop 1.26.2 的服务器监控与 SSH 工作台基础上增加模型训练。训练在已配置的远程 Linux 服务器上执行，Windows 客户端负责配置和查看状态。

## 开始训练

1. 添加服务器或沿用升级前的服务器配置，核对首次 SSH 连接的主机指纹。
2. 打开侧栏“模型训练”，新建训练配置。
3. 选择服务器，填写训练名称、工作目录、训练脚本路径和配置文件路径。文件应已存在于服务器；相对路径以工作目录为基准，支持 `~`。
4. 核对启动前缀和附加参数；配置文件默认使用位置式传参，也可切换参数式。
5. 从右侧所有服务器的 GPU 总览直接选择显卡，可选择当前繁忙的卡，并设定每卡最低空闲显存。切换服务器会清空之前的选卡，同一次训练只使用一台服务器。
6. 检查路径和环境，核对最终命令，提交训练。繁忙时弹窗列出原因，确认“后台排队”才会提交等待任务。

配置可以保存并重复使用。提交的任务保存独立的配置快照，之后编辑模板不会改变已排队任务的命令；训练代码和配置文件仍是服务器上的原有文件。

## 项目分类与重点色

训练配置中的“项目分类”独立于“我的项目”同步配置。可选择已有分类或直接填写新项目名，并设置项目重点色；同名项目共用颜色，保存颜色变更会同步该项目下的全部训练配置。新项目自动分配未使用的颜色，旧配置显示为“未分类”。

“训练配置”顶部按项目列出索引和配置数量。点击项目可快速筛选，卡片边缘及项目标记使用对应重点色；在项目索引下新建训练会默认归入当前项目。修改分类或颜色不改变已经提交的训练任务。

“训练任务”和“训练配置”看板会将同名项目合并为一组，未填写项目的条目归入“未分类”。点击项目标题可单独收起或展开，两个看板各自保留展开状态；收起只隐藏组内卡片，不更改配置、任务状态或已选择的历史记录。“进行中”“最近结束”和项目筛选仍按原条件显示对应条目。

## 生成 datalist（可选）

配置首行可填写服务器上已有的 datalist 生成脚本及其参数。相对脚本路径以工作目录为基准，复用下方的 Python / Conda 启动前缀；生成步骤默认设置 `CUDA_VISIBLE_DEVICES=''`。不会自动附加训练配置文件，需要的配置或输出路径请明确填写在“生成脚本参数”中。脚本留空时保持原训练流程。

点击“开始训练”并确认提交后，服务器立即生成一次 datalist，同时检测 GPU 空闲状态。仅保存配置、检查路径或尚未确认后台排队时不会执行脚本。生成成功且指定 GPU 连续空闲 30 秒后才启动正式训练；生成失败或中断时停止该任务，不自动重新生成或开训。

生成状态显示在任务列表，生成脚本与训练输出写入同一任务日志并分段标记。取消任务也会停止正在运行的生成脚本及其子进程；客户端退出不影响服务器已接受的任务。恢复队列或重试同一任务不会重复执行已完成的生成步骤，新建任务则各自生成一次。

新配置按服务器编号（优先匹配主机 IPv4 尾号）填写启动前缀，用户名取服务器的 SSH 用户：20、21、23 使用 `/home/<用户名>/miniconda3/envs/torch29-cu130/bin/python`；22、26、27、28 使用 `/home/<用户名>/miniconda3/envs/deploy/bin/python`。其他服务器默认 `python -u`。切换服务器时自动前缀随之更新；手工填写的自定义前缀会保留，已保存的配置保持原值。

## 命令示例

| 运行方式 | 启动前缀 | 脚本 | 配置方式 | 附加参数 |
| --- | --- | --- | --- | --- |
| Python | `/opt/venvs/train/bin/python -u` | `train.py` | 参数式：`--config`，文件 `configs/train.yaml` | `--epochs 100` |
| Conda | `/opt/miniconda3/bin/conda run --no-capture-output -n train python -u` | `tools/train.py` | 参数式：`--cfg`，文件 `configs/model.yaml` | `--seed 42` |
| 位置参数 | `python3 -u` | `train.py` | 位置式：文件 `configs/train.json` | 留空或填写脚本所需参数 |
| torchrun | `/opt/venvs/train/bin/torchrun --standalone --nproc_per_node=2` | `train.py` | 参数式：`--config`，文件 `configs/ddp.yaml` | `--epochs 100` |

路径中有空格时，在路径字段直接填写完整路径；前缀和附加参数中的单个参数有空格时需要引号。启动前缀应使用服务器能找到的程序，推荐填写绝对路径。

平台按所选 GPU 的 UUID 自动设置 `CUDA_VISIBLE_DEVICES`，避免 CUDA 与驱动卡号排序不同而用错卡；训练脚本中看到的卡号从 0 开始。不要在前缀中再填写该变量。`torchrun` 的进程数应与所选 GPU 数量一致。
启动前缀和附加参数按参数列表执行，支持 Python、`conda run`、`torchrun`，不支持 `source`、`&&`、管道、重定向或自行添加 `nohup`。平台负责工作目录、后台运行与日志。

## 空闲条件与排队

GPU 选择界面和远端队列使用同一显存规则：每卡空闲显存达到你设置的阈值即满足资源条件，新配置默认 10 GB。修改该数值会立即更新所有服务器显卡的显示。计算进程数和利用率仅用于展示，不阻止提交或开训。

固定选择的全部 GPU 必须同时满足以下条件，且连续稳定 30 秒：

- 每张卡的空闲显存达到任务设定的最低 GB 数。
- GPU 显存指标可读，所选设备仍可见。

即使提交时已经空闲，也会先进入“空闲确认中”，稳定 30 秒且可选的 datalist 生成步骤完成后自动启动。
等待期间显存条件失效会重新计时；显存指标读取失败时继续等待，不会把未知状态当作空闲。进程查询失败或利用率不可读不会否决可确认的显存容量。

重叠 GPU 的任务按提交顺序等待，较早的多卡任务会保留对这些卡的排队优先级，避免被后来的单卡任务反复插队。互不重叠的 GPU 任务可以并行。
固定卡号通过 GPU UUID 记录，启动前重新解析实际卡号并复查条件。

队列及训练运行器独立运行在服务器上。关闭 ModelGym、电脑休眠或 SSH 断开不会结束已经接受的等待或训练任务；重新连接后查询服务器状态。
网络响应丢失时，应重试同一个提交操作或刷新列表，平台会按任务标识去重。

## 状态、日志与取消

“最近结束”支持勾选已完成、失败或已取消的记录，也可全选后点击“删除所选记录及日志”。确认框会列出本次选中的任务和服务器；确认后永久清理本机记录与对应服务器上 ModelGym 管理的任务记录、datalist / 训练输出日志。项目代码、数据集、模型权重和可复用训练配置会保留。

运行或排队中的任务不能删除；已结束但仍有训练或 datalist 子进程尚未退出的任务也会保留。连接或清理失败的项会显示原因，可重新勾选重试；同批次中其他已清理的项正常移除。清理中断后可以重试，刷新、离线或重开不会恢复已确认删除的记录。

训练成功或失败后，应用右下角弹出结果提醒，可直接进入“最近结束”查看任务；主动取消不重复提醒。切换到其他页面仍会检测，同一任务只提醒一次。应用需要保持运行才能及时发出提醒；已观察到的任务在客户端离线期间结束，会在重新连接后提醒。首次打开不会为全部历史任务集中弹窗。系统桌面通知遵循现有通知总开关和系统权限，应用内提示不依赖系统通知权限。

- “排队中”显示当前等待原因；“空闲确认中”显示稳定确认进度。
- “训练中”可查看最近的日志，并可确认停止训练及其进程组。
- 等待任务可取消，取消与发车共用同一状态锁，避免取消后又启动。
- 正常结束、失败、取消都有记录；训练程序失败不会自动重跑。
- SSH 断线时保留最后已知状态并提示连接错误，不把断线误判为训练失败。
- 如果远端持久任务记录损坏，队列会保留原文件、明确报错并暂停自动启动，避免把无法确认的任务当作不存在；修复记录后可恢复队列。
- 服务端重启或守护进程意外退出后，重新查询不会静默重新运行任务；仍在等待的任务可通过“恢复队列”操作恢复调度。运行中的任务中断后不会自动重训。

## 远程环境要求和边界

训练日志开头记录实际解析的工作目录、最终命令和 GPU UUID。工作目录决定相对文件路径的基准；填写绝对脚本路径不会自动切换到脚本目录。建议项目脚本使用项目根目录，并区分启动工作目录与训练配置中的输出目录（例如 `work_dir`）。修改路径或环境后，应重新检查。

训练连接通过无 PTY 的交互式登录 Bash 加载用户已有的 Shell 启动环境，再执行队列请求。datalist 和后台训练继承该环境中的动态库搜索路径；启动前缀仍决定实际使用哪个 Python、Conda 或 torchrun，平台不会将训练参数作为 Shell 脚本执行。Bash 启动文件的加载规则见 [Bash 官方说明](https://www.gnu.org/software/bash/manual/html_node/Bash-Startup-Files.html)。

如果终端里同一 Python 能导入模块，平台却报告 `ImportError: libopencv_gapi.so.405: cannot open shared object file` 等错误，应先对照 Shell 环境及 `LD_LIBRARY_PATH`，不能仅凭报错判断需要重装包。仅在某个终端手工 `export` 的变量不会自动出现在新的 SSH 会话中；需要的环境应由服务器用户已有的启动文件或明确的 Conda 启动前缀建立。路径检查通过只说明目录、文件及可执行程序可用，不保证训练脚本的所有依赖可以成功导入。

新提交或明确“恢复队列”时，平台会核对守护进程的程序版本及训练相关环境指纹，必要时只替换调度器，使其使用当前环境；已经运行的 datalist 和训练进程保留。查询列表和检查路径不会自动恢复或重跑任务。已经失败的任务需要确认后重新提交，避免重复生成数据或训练。

远端需要 Linux、Bash、Python 3.8 或更高版本、可用的 NVIDIA 驱动与 `nvidia-smi`，以及训练脚本所需的环境和依赖。首版训练队列支持 NVIDIA 物理 GPU，不支持 MIG 分区、跨服务器分布式训练或 Ascend/NPU 训练调度；原有监控功能保持可用。

队列状态和日志保存在 SSH 用户的私有 `~/.racktop/modelgym-training/` 子目录内，并按执行主机隔离。通常不需要 root 权限。凭据仍由原有 SSH/系统安全凭据机制管理，不写入训练配置。

ModelGym 的锁协调自己提交的训练，不会终止其他用户的任务，也无法阻止其他人在终端手动抢用 GPU。需要集群级资源强制隔离时，应由服务器管理员使用专门调度系统。

## 从 RackTop 升级

Windows 安装前先关闭原 RackTop，包括托盘中的旧进程，再运行 ModelGym 安装程序并选择升级。
ModelGym 保留原应用标识、`racktop.sqlite`、系统凭据服务和 SSH 密钥命名，继承原有服务器、配置和历史；新的训练配置与作业索引使用单独的 `modelgym-training.sqlite`。
名称中保留 `racktop` 的兼容目录不是安装错误，请勿手动删除。

本分支已关闭原 RackTop 自动更新源，防止 ModelGym 被更新回上游产品。后续使用 ModelGym 安装包手动升级。
卸载时如果选择删除应用数据，仍会删除保留的配置和历史；常规升级不选择删除数据。
