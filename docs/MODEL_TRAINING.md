# ModelGym 模型训练

ModelGym 在 RackTop 1.26.2 的服务器监控与 SSH 工作台基础上增加模型训练。训练在已配置的远程 Linux 服务器上执行，Windows 客户端负责配置和查看状态。

## 开始训练

1. 添加服务器或沿用升级前的服务器配置，核对首次 SSH 连接的主机指纹。
2. 打开侧栏“模型训练”，新建训练配置。
3. 选择服务器，填写训练名称、工作目录、训练脚本路径和配置文件路径。文件应已存在于服务器；相对路径以工作目录为基准，支持 `~`。
4. 填写启动前缀和附加参数，选择配置文件的传参方式。
5. 选择固定的 GPU，可选择当前繁忙的卡，并设定每卡最低空闲显存。
6. 检查路径和环境，核对最终命令，提交训练。繁忙时弹窗列出原因，确认“后台排队”才会提交等待任务。

配置可以保存并重复使用。提交的任务保存独立的配置快照，之后编辑模板不会改变已排队任务的命令；训练代码和配置文件仍是服务器上的原有文件。

## 命令示例

| 运行方式 | 启动前缀 | 脚本 | 配置方式 | 附加参数 |
| --- | --- | --- | --- | --- |
| Python | `/opt/venvs/train/bin/python -u` | `train.py` | 参数式：`--config`，文件 `configs/train.yaml` | `--epochs 100` |
| Conda | `/opt/miniconda3/bin/conda run --no-capture-output -n train python -u` | `tools/train.py` | 参数式：`--cfg`，文件 `configs/model.yaml` | `--seed 42` |
| 位置参数 | `python3 -u` | `train.py` | 位置式：文件 `configs/train.json` | 留空或填写脚本所需参数 |
| torchrun | `/opt/venvs/train/bin/torchrun --standalone --nproc_per_node=2` | `train.py` | 参数式：`--config`，文件 `configs/ddp.yaml` | `--epochs 100` |

路径中有空格时，在路径字段直接填写完整路径；前缀和附加参数中的单个参数有空格时需要引号。启动前缀应使用服务器能找到的程序，推荐填写绝对路径。

平台按所选 GPU 的 UUID 自动设置 `CUDA_VISIBLE_DEVICES`，避免 CUDA 与驱动卡号排序不同而用错卡；训练脚本中看到的卡号从 0 开始。不要在前缀中再填写该变量。`torchrun` 的进程数应与所选 GPU 数量一致。
启动前缀和附加参数按参数列表执行，支持 Python、`conda run`、`torchrun`，不支持 `source`、`&&`、管道、重定向或自行添加 `nohup`。平台负责工作目录、后台运行与日志。

## 空闲条件与排队

固定选择的全部 GPU 必须同时满足以下条件，且连续稳定 30 秒：

- 没有计算进程，包括当前用户自己的其他计算进程。
- GPU 利用率不高于 10%。
- 每张卡的空闲显存达到任务设定的最低 GB 数。
- GPU 与计算进程指标可读，所选设备仍可见。

即使提交时已经空闲，也会先进入“空闲确认中”，稳定 30 秒后自动启动。
等待期间任一条件失效会重新计时；指标读取失败时继续等待，不会把未知状态当作空闲。

重叠 GPU 的任务按提交顺序等待，较早的多卡任务会保留对这些卡的排队优先级，避免被后来的单卡任务反复插队。互不重叠的 GPU 任务可以并行。
固定卡号通过 GPU UUID 记录，启动前重新解析实际卡号并复查条件。

队列及训练运行器独立运行在服务器上。关闭 ModelGym、电脑休眠或 SSH 断开不会结束已经接受的等待或训练任务；重新连接后查询服务器状态。
网络响应丢失时，应重试同一个提交操作或刷新列表，平台会按任务标识去重。

## 状态、日志与取消

- “排队中”显示当前等待原因；“空闲确认中”显示稳定确认进度。
- “训练中”可查看最近的日志，并可确认停止训练及其进程组。
- 等待任务可取消，取消与发车共用同一状态锁，避免取消后又启动。
- 正常结束、失败、取消都有记录；训练程序失败不会自动重跑。
- SSH 断线时保留最后已知状态并提示连接错误，不把断线误判为训练失败。
- 如果远端持久任务记录损坏，队列会保留原文件、明确报错并暂停自动启动，避免把无法确认的任务当作不存在；修复记录后可恢复队列。
- 服务端重启或守护进程意外退出后，重新查询不会静默重新运行任务；仍在等待的任务可通过“恢复队列”操作恢复调度。运行中的任务中断后不会自动重训。

## 远程环境要求和边界

远端需要 Linux、Python 3.8 或更高版本、可用的 NVIDIA 驱动与 `nvidia-smi`，以及训练脚本所需的环境和依赖。首版训练队列支持 NVIDIA 物理 GPU，不支持 MIG 分区、跨服务器分布式训练或 Ascend/NPU 训练调度；原有监控功能保持可用。

队列状态和日志保存在 SSH 用户的私有 `~/.racktop/modelgym-training/` 子目录内，并按执行主机隔离。通常不需要 root 权限。凭据仍由原有 SSH/系统安全凭据机制管理，不写入训练配置。

ModelGym 的锁协调自己提交的训练，不会终止其他用户的任务，也无法阻止其他人在终端手动抢用 GPU。需要集群级资源强制隔离时，应由服务器管理员使用专门调度系统。

## 从 RackTop 升级

Windows 安装前先关闭原 RackTop，包括托盘中的旧进程，再运行 ModelGym 安装程序并选择升级。
ModelGym 保留原应用标识、`racktop.sqlite`、系统凭据服务和 SSH 密钥命名，继承原有服务器、配置和历史；新的训练配置与作业索引使用单独的 `modelgym-training.sqlite`。
名称中保留 `racktop` 的兼容目录不是安装错误，请勿手动删除。

本分支已关闭原 RackTop 自动更新源，防止 ModelGym 被更新回上游产品。后续使用 ModelGym 安装包手动升级。
卸载时如果选择删除应用数据，仍会删除保留的配置和历史；常规升级不选择删除数据。
